# Security policy

Keep the bearer token only in a private env file, never in source control; rotate it immediately after suspected exposure. Tokens never belong in git. Keep persistent queue state in an operator-created 0700 directory.

The bridge binds to loopback. Remote access requires an operator-controlled, authenticated TLS reverse proxy. The bearer-authenticated MCP adapter is constructed around one principal-bound queue object; MCP schemas contain no source, producer, worker, agent, or destination overrides. `agent-bus-endpoint` is a separate local command. Its process id is the sender, and it cannot choose another sender. It can create a chat or a pointer only on an allowlisted edge. A separate TLS host can serve the same state directory to clients on other machines. Each enrolled client certificate maps to one endpoint. The host refuses plaintext HTTP and refuses `0.0.0.0`. Enrollment and revocation are a local file edited by `agent-bus-enroll`, not a remote tool. See `docs/REMOTE.md`. A connected client may hold `wait_available` on that connection. The host does not dial out, and the call does not start a stopped agent. The MCP server can bind to one endpoint in that same allowlist with `AGENT_BUS_CONFIG` and `AGENT_BUS_ENDPOINT_ID` when the legacy producer and worker variables are unset. That process claims, answers, posts, reads, polls, and acknowledges as that endpoint. Tool arguments cannot select a different author or endpoint. Reading or polling a board does not acknowledge it. Acknowledgement names exact post ids and is replay-stable. A board post does not create work. Only that author can promote the post, and only to one other member. `read_result` returns the stored result only to the endpoint that promoted the post which created the task. Every other endpoint is refused, and a task that was not promoted from a board is refused. The two-machine helper refuses `100.64.0.0/10` unless `AGENT_BUS_ALLOW_TAILSCALE` is exactly `1`, and that opt-in adds no other range. The simple pair has no board. A board is a member list in the allowlist, not a public board. Principal identities are restricted to exact built-in strings containing 1–64 ASCII letters, digits, `_`, or `-`; Unicode identities are refused. `RoutePolicy` is a closed directional allowlist, each edge separately allows `task` and/or `consultation`, and the exact policy is bound to the state root. Opening a parent-format root without `policy.json` validates every stored producer-to-worker edge and record mode before persisting the proposed policy; one incompatible record refuses the migration without changing records. A worker can claim or finish only records addressed to its configured principal. A consultation answer stays readable by its producer. A promoted task result is readable only by the promoting endpoint, as stated above.

Reference validation accepts only syntactic public HTTPS; it does not establish source safety or trustworthiness. Treat task goals, references, results, consultation questions, origin references, and answers as untrusted input. Consultation schemas provide no fields for attachments, task state, or execution authority. Do not put commands or credentials in consultation free text; answers remain advice-only and cannot change task state.

This package is one local durable core. It is not multi-host federation, service discovery, replicated storage, or consensus. The optional TLS host encrypts its own clients and checks their certificates. It does not dial out. An operator adding an adapter must authenticate its agent principal before constructing or selecting the corresponding bound queue object.

`ask` is an optional outbound NATS client. The operator sets `AGENT_BUS_NATS_URL`. This package does not listen for NATS, and the call does not create a board post, a task, or a consultation. Treat the question and the answer as untrusted text.

The public-research producer and its manifest are an example workload, not the product. Its reserved `.invalid` reference must not be treated as live content.

Report vulnerabilities privately through a GitHub Security Advisory. Do not place secrets, task contents, or state records in a public report.
